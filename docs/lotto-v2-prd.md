# 1. 프로젝트 개요

LOTTO LAB V2는 단순한 랜덤 번호 생성기가 아니다.

로그인한 사용자에게 매주 5개의 추천 게임을 제공하고, 각 게임에 서로 다른 추천 전략을 적용하여 실제 로또 당첨번호와 비교·분석하는 **개인 데이터 실험 서비스**를 목표로 한다.

핵심 개념:

```text
주간 5게임
↓
5개 알고리즘
↓
전략별 1게임 추천
↓
실제 당첨번호와 비교
↓
개인별 누적 성적 저장
↓
전략별 장기 성능 비교
```

본 서비스는 과거 당첨번호를 활용한 데이터 분석 실험을 제공하지만, 특정 번호가 실제 당첨될 확률을 높여준다고 주장하지 않는다.

# 2. 핵심 사용자 경험

사용자는 로그인 후 LOTTO LAB에 접속한다.

기본 흐름:

```text
로그인
↓
현재 대상 회차 확인
↓
지난 회차 당첨번호 확인
↓
이번 주 추천 5게임 생성
↓
5개 전략별 추천번호 확인
↓
DB 저장
↓
추첨 종료
↓
실제 당첨번호 입력 또는 자동 반영
↓
추천결과 자동 비교
↓
개인 누적 성적 업데이트
↓
다음 회차에서 새 5게임 생성 가능
```

# 3. 주간 추천 제한

사용자 1명당 **회차별 최대 5게임**만 생성할 수 있다.

5게임은 임의로 여러 번 뽑는 방식이 아니라 **5개 전략별 1게임씩 고정**한다.

```text
GAME 1 → RANDOM
GAME 2 → FREQUENCY
GAME 3 → RECENCY
GAME 4 → BALANCED
GAME 5 → LUCID MODEL
```

총 5게임이 생성되면 해당 회차에서는 추가 생성할 수 없다.

다음 회차가 시작되면 다시 5게임을 생성할 수 있다.

# 4. 추천 전략

## 4.1 RANDOM

완전 무작위 방식.

조건:

- 1~45
- 중복 없는 6개
- 오름차순 정렬

목적:

다른 전략과 비교하기 위한 기준군.

---

## 4.2 FREQUENCY

과거 당첨번호의 장기 출현 빈도를 활용하는 전략.

활용 데이터 예:

- 전체 누적 출현 횟수
- 번호별 출현 비율

단, 단순히 많이 나온 번호만 고정적으로 선택하지 않도록 무작위성을 일부 유지할 수 있다.

---

## 4.3 RECENCY

최근 회차의 데이터에 상대적으로 높은 가중치를 주는 전략.

예:

- 최근 10회
- 최근 20회
- 최근 30회

정확한 가중 방식은 별도 알고리즘 문서에서 정의한다.

---

## 4.4 BALANCED

번호 조합의 균형을 우선하는 전략.

고려 요소 예:

- 홀짝 비율
- 저번호 / 고번호 분포
- 번호 구간 분포
- 번호 합계
- 연속 번호 수
- 동일 끝자리 과다 여부

특정 패턴을 보장하지 않으며, 지나치게 편중된 조합을 피하는 역할을 한다.

---

## 4.5 LUCID MODEL

여러 통계 조건을 조합한 자체 실험 전략.

향후 다음 요소를 조합할 수 있다.

- Frequency
- Recency
- Long Absence
- Balanced
- Weighting
- 과거 전략별 실적

LUCID MODEL은 향후 지속적으로 개선 가능한 별도 모듈로 구현한다.

# 6. 회차 관리

LOTTO LAB은 모든 기능을 **로또 회차 기준**으로 관리한다.

예:


- upcoming
- open

# 8. 이번 주 추천 UI

사용자에게 이번 회차의 추천 진행 상태를 표시한다.


저장 정보:

```text

number_3

number_6

```

필요하면 번호는 JSON 또는 별도 정규화 구조로 저장할 수 있다.

구체적인 DB 구조는 기술 설계에서 결정한다.

# 15. 주간 초기화 방식

회차가 바뀔 때 과거 데이터를 삭제하지 않는다.

화면에서는 새 회차가 시작된 것처럼 초기화하지만 DB에서는 기록을 누적 유지한다.

예:

```text

5게임 추천 완료
결과 저장

↓

1301회 시작
0 / 5 GAME
새 추천 가능
```

이 구조를 통해 장기 성적 분석이 가능하다.

# 21. 재생성 정책

한 회차에 한 번 생성된 전략별 추천번호는 기본적으로 다시 생성할 수 없다.

목적:

- 사용자가 마음에 드는 번호가 나올 때까지 반복 생성하는 것을 방지
- 전략 비교의 공정성 유지
- 기록 일관성 유지

관리자용 테스트 환경에서는 별도 예외 기능을 둘 수 있다.

# 22. 데이터 무결성

# 29. 성공 기준

LOTTO LAB V2는 다음 조건을 만족하면 성공이다.

1. 로그인 사용자가 회차당 정확히 5게임만 생성할 수 있다.
2. 5게임은 5개 전략에 각각 1개씩 대응한다.
3. 생성된 번호는 DB에 저장된다.
4. 회차가 바뀌면 새로운 5게임을 생성할 수 있다.
5. 과거 기록은 삭제되지 않는다.
6. 추첨번호 등록 후 자동으로 적중결과가 계산된다.
7. 개인 누적 성적을 조회할 수 있다.
8. 전략별 성적을 비교할 수 있다.
9. 새로운 당첨 데이터가 이후 추천 계산에 반영된다.
10. 특정 전략이 실제 당첨 가능성을 높인다고 과장하지 않는다.

# 30. Final Concept

LOTTO LAB V2의 핵심은 번호를 맞히는 것이 아니라 **5개의 서로 다른 전략을 동일 조건에서 반복 실험하고 그 결과를 장기간 데이터로 비교하는 것**이다.

```text
5 STRATEGIES
↓
5 WEEKLY PICKS
↓
REAL DRAW
↓
COMPARE
↓
ACCUMULATE
↓
LEARN
```

**LOTTO LAB = Probability · Data · Experiment**
